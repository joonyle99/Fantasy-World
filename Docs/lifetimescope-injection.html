LifetimeScope와 주입 노트

VContainer가 씬 스코프 체인을 타고 의존성을 채워 넣는 과정을, 호출 순서 그대로 두 사례로 추적한다 — TitleMenu가 GameFlow를 받는 흐름, 그리고 WorldFlow._scope가 WorldLifetimeScope가 되는 원리.

01

TitleMenu ← GameFlow 주입

TitleLifetimeScope.Configure는 한 줄이다 — builder.RegisterComponentInHierarchy<TitleMenu>(). 여기서 TitleMenu가 GameFlow를 어떻게 받게 되는지, "부모에서 물려받는다"는 말 대신 실제 순서로 본다.

등장인물

이름정체
GameLifetimeScope부모 스코프 (Bootstrap 씬). LifetimeScope는 실행 순서가 크게 앞당겨져 있음(DefaultExecutionOrder)
부모 컨테이너GameLifetimeScope가 빌드한 IObjectResolver. GameFlow 싱글턴을 붙잡고 있음
TitleLifetimeScope자식 스코프 (Title 씬). Awake를 오버라이드 안 함 → LifetimeScope.Awake 그대로
자식 컨테이너TitleLifetimeScope가 빌드할 IObjectResolver. 부모 컨테이너로의 참조를 가짐
TitleMenuTitle 씬 Canvas에 붙은 MonoBehaviour

T0 · 부트스트랩 (Title 로드보다 한참 전)

  1. GameLifetimeScope.Awake() → base.Awake() → 내부적으로 Build()

  2. Configure(builder) 실행 → builder.RegisterEntryPoint<GameFlow>().AsSelf() 등록

  3. builder.Build() → 부모 컨테이너 생성

  4. GameFlow는 EntryPoint라서 빌드 시점에 인스턴스가 즉시 생성된다. 생성자 파라미터를 컨테이너가 채운다:

    new GameFlow(sceneLoader, audioService, inputService, scope)
                                                       ↑ 이 scope = GameLifetimeScope 자기 자신
                                                         (VContainer가 소유 LifetimeScope를 자동 등록)

    → 이게 앱 전체에서 유일한 GameFlow 인스턴스. 부모 컨테이너가 싱글턴으로 붙잡는다.

  5. .AsSelf() 덕분에 부모 컨테이너 등록표에 typeof(GameFlow) → 그 인스턴스 매핑이 생긴다. (없으면 IAsyncStartable로만 조회됨)

  6. GameFlow.StartAsync() 실행 → … → SceneLoader.LoadAsync("Title", 이_GameLifetimeScope)

T1 · "다음 스코프의 부모는 이거다" 예약

  1. 정적 메서드 LifetimeScope.EnqueueParent(gameScope) 호출

    • 전역 스택에 gameScope를 push하고 IDisposable을 반환
    • 의미: "지금부터 Awake하는 LifetimeScope는 이걸 부모로 삼아라"

  2. using 블록 안에서 await SceneManager.LoadSceneAsync("Title", Single)

    using (LifetimeScope.EnqueueParent(gameScope))
{
    await SceneManager.LoadSceneAsync("Title", Single);   // ← T2가 이 블록 안에서 일어남
}
핵심

이 using 블록이 await를 가로질러 열려 있다. 자식 스코프의 Awake가 로드 도중에 실행되므로, 그때까지 부모 예약이 유효해야 하기 때문.

T2 · 씬 로드, 그 안에서 자식 스코프 Awake (전부 동기, await 풀리기 전)

  1. Unity가 Title.unity 로드. Bootstrap은 언로드되지만 GameLifetimeScope의 GameObject는 DontDestroyOnLoad → 생존. 부모 컨테이너도 그대로.

  2. Title 씬 오브젝트 생성. Unity가 Awake 호출 시작. LifetimeScope는 실행 순서가 앞당겨져 있어 → TitleLifetimeScope.Awake()가 TitleMenu보다 먼저

  3. TitleLifetimeScope.Awake() → base.Awake(): 부모 찾기 (우선순위)

    1. 인스펙터 Parent 슬롯 — 안 꽂음
    2. EnqueueParent로 예약된 것 — T1에서 push한 gameScope 발견 ✔
    3. 씬에서 LifetimeScope 타입 검색 — 여기까진 안 감

    → parent = GameLifetimeScope 확정

  4. 자식 컨테이너 빌드 — 부모 컨테이너로부터 자식 스코프 생성

    • 새 IObjectResolver 생성, 내부에 Parent = 부모 컨테이너 참조 저장
    • Configure(builder) 실행 → builder.RegisterComponentInHierarchy<TitleMenu>()
    • ⚠ 지금 TitleMenu를 찾지 않는다. "빌드할 때 이 스코프가 속한 씬에서 TitleMenu를 찾아 등록하라"는 규칙만 적는다

  5. 자식 builder.Build() 실행:

    • RegisterComponentInHierarchy 규칙 발동 → this.gameObject.scene.GetRootGameObjects() 순회 → 각 루트에 GetComponentInChildren<TitleMenu>(includeInactive: true) → 씬의 TitleMenu 인스턴스 발견
    • 그 인스턴스를 자식 컨테이너에 싱글턴으로 등록. RegisterComponent* 계열로 등록됐으므로 주입 대상으로 표시됨

T3 · 주입 실행 (여기서 _gameFlow가 채워짐)

  1. 빌드 마무리 단계에서 자식 컨테이너가 등록된 컴포넌트들에 Inject() 수행:

    • TitleMenu를 리플렉션으로 스캔 → [Inject] 붙은 Construct(GameFlow gameFlow) 메서드 발견
    • Construct를 호출하려면 GameFlow를 resolve 해야 함:
    단계조회 위치결과
    a자식 컨테이너 등록표GameFlow 없음
    bParent 참조 따라 부모 컨테이너typeof(GameFlow) 등록 있음 (T0·5)
    c부모가 반환T0·4에서 만든 그 싱글턴 인스턴스

    titleMenu.Construct(그_GameFlow) 호출 → TitleMenu._gameFlow = gameFlow ✅

  2. TitleLifetimeScope.Awake() 반환. 여기까지 전부 동기적으로 완료.

T4 · 나머지 Unity 생명주기

  1. Unity가 TitleMenu.OnEnable() 호출 (우리 TitleMenu엔 Awake 없음)

    • 이 시점 _gameFlow는 이미 T3에서 채워짐 → _startButton.onClick.AddListener(OnStartClicked) 안전

  2. await SceneManager.LoadSceneAsync 완료 → LoadAsync의 await 풀림

  3. using 블록 종료 → EnqueueParent가 준 IDisposable.Dispose() → 전역 스택에서 gameScope pop (다음에 로드될 World 씬 스코프가 엉뚱한 부모를 물지 않도록)

  4. GoToTitle 이어서: ChangeState(GameState.Title)

T5 · 버튼 클릭

  1. 유저가 Start 클릭 → OnStartClicked() → _gameFlow.StartGame().Forget()

    → T3에서 주입받은 그 싱글턴 GameFlow의 메서드 호출. 새 인스턴스 안 생김.

요약 · 3개의 축

축무엇
부모 연결EnqueueParent(정적 스택) → TitleLifetimeScope.Awake가 읽음 → 자식 컨테이너가 부모 컨테이너 참조를 들고 있음
컴포넌트 발견RegisterComponentInHierarchy = "빌드 시 씬에서 찾아 등록 + 주입" 규칙
resolve 알고리즘자식에서 못 찾으면 부모로, 부모에서 못 찾으면 조부모로 (단방향 상향 탐색). GameFlow는 부모(Game)에 있으므로 자식(Title)에서 요청 시 부모까지 올라가 싱글턴을 받음
02

_scope가 WorldLifetimeScope인 이유

public WorldFlow(SceneLoader sceneLoader, AudioService audioService, GameSounds sounds, LifetimeScope scope)
{
    _sceneLoader  = sceneLoader;
    _audioService = audioService;
    _sounds       = sounds;
    _scope        = scope;   // ← 왜 이게 WorldLifetimeScope 인가?
}

한 문장

모든 LifetimeScope는 자기 컨테이너를 빌드할 때, 맨 먼저 LifetimeScope 타입으로 "자기 자신"을 등록한다. 그래서 그 컨테이너가 만든 클래스가 생성자에 LifetimeScope를 요구하면 → 그 스코프 본인을 받는다.

WorldFlow 생성자 4개 파라미터의 출처

WorldFlow는 WorldLifetimeScope.Configure에서 RegisterEntryPoint<WorldFlow>()로 등록됐다 → World 컨테이너가 생성자를 호출한다. 각 파라미터를 resolve하는 과정:

파라미터World 컨테이너에 있나?최종 출처
SceneLoader sceneLoader없음 → 부모로Game 컨테이너 · Register<SceneLoader>(Singleton)
AudioService audioService없음 → 부모로Game 컨테이너
GameSounds sounds있음 · RegisterInstance(_gameSounds)World 컨테이너
LifetimeScope scope있음 — 빌드 시 자동 등록된 자기 자신World 컨테이너 → WorldLifetimeScope 인스턴스

resolve 규칙의 비대칭

resolve는 항상 "내 컨테이너 먼저, 없으면 부모로 상향". 같은 요청이라도 어디서 멈추느냐가 다르다:

Game 컨테이너
SceneLoaderAudioServiceSaveSystemGameFlow LifetimeScope = GameLifetimeScope
▲ Parent
World 컨테이너
GameSoundsGameplayEventBusObjectiveManagerWorldFlow LifetimeScope = WorldLifetimeScope
▲ Parent
Area 컨테이너
AreaObjectiveSetAreaFlow LifetimeScope = AreaLifetimeScope
World 에서 HIT WorldFlow가 LifetimeScope 요청 → World 컨테이너에 이미 있어서(자기 자신) 탐색 종료 → WorldLifetimeScope
World MISS → Game HIT WorldFlow가 SceneLoader 요청 → World 컨테이너에 없어서 ▲ Game 까지 올라가 찾음

즉 같은 LifetimeScope 타입 요청이라도 "누가 만들었느냐"가 "어느 스코프를 받느냐"를 결정한다:

GameFlow  가 요청  →  Game 컨테이너가 생성   →  _scope = GameLifetimeScope
WorldFlow 가 요청  →  World 컨테이너가 생성  →  _scope = WorldLifetimeScope
AreaFlow  가 요청  →  Area 컨테이너가 생성   →  _scope = AreaLifetimeScope

왜 이 설계가 필요한가

WorldFlow는 이렇게 쓴다:

await _sceneLoader.LoadAdditiveAsync("Area_Garden", _scope, setActive: true);

_scope가 반드시 WorldLifetimeScope여야, SceneLoader 안의 LifetimeScope.EnqueueParent(_scope)가 실행됐을 때 → Area_Garden 씬의 AreaLifetimeScope가 WorldLifetimeScope를 부모로 물게 된다. 그래야 Area 씬의 NPC·목표존이 World 레벨의 GameplayEventBus, GooseController, ObjectiveManager를 주입받을 수 있다.

같은 패턴, 한 계층 아래

GameFlow._scope(=GameLifetimeScope)를 World 로드에 넘기는 것과 정확히 같은 일이, 한 계층 아래에서 반복된다:

GameFlow  : LoadAsync("World", GameLifetimeScope)                → World 의 부모 = Game
WorldFlow : LoadAdditiveAsync("Area_Garden", WorldLifetimeScope) → Area 의 부모 = World
