GameFlow와 async 노트

Phase 2에서 들어온 타이틀 씬 · 일시정지 시스템의 로직과, 그 코드가 기대는 async / await / UniTask를 코루틴 경험에 얹어 정리한다.

01

타이틀 · 일시정지 흐름

상태 하나로 흐름을 표현

GameState enum(Booting → Title → Loading → Playing ⇄ Paused)을 GameFlow가 소유한다. 상태를 바꿀 때마다 씬 로드 · Time.timeScale · 입력을 조작한다.

  • GameStateController<GameState> — JoonyleGameDevKit의 가벼운 enum 상태기. ChangeState(next) 하면 OnStateChanged(prev, next) 이벤트가 발행된다.
  • GameFlow는 이 내부 이벤트를 자기 public event StateChanged로 그대로 전달한다 → 뷰(PauseMenuView)가 구독한다.
기억할 것

모든 전환은 Loading을 거친다 — ChangeState(Loading) → await 씬 로드 → 목적지 상태. _busy 플래그가 전환 도중의 재진입을 막는다.

부팅 시퀀스

Bootstrap 씬에는 GameLifetimeScope 하나만 있다.

  1. GameLifetimeScope.Awake() → base.Awake()에서 컨테이너가 빌드된다.

  2. 빌드 중 EntryPoint가 즉시 생성된다 — InputService(IInitializable → Initialize() 호출, 액션 활성화), 이어서 GameFlow(IAsyncStartable → StartAsync() 호출).

  3. Awake()로 돌아와 DontDestroyOnLoad(gameObject) — 씬이 바뀌어도 이 스코프는 생존한다.

  4. GameFlow.StartAsync가 구독을 걸고 타이틀로 향한다.

    async UniTask StartAsync(CancellationToken cancellation)
{
    _stateController.OnStateChanged += OnStateChanged;   // 내부 → public 전달
    _inputService.PausePerformed    += TogglePause;      // Esc 구독

    await GoToTitle();
}

Title 씬 로드 — GoToTitle

private async UniTask GoToTitle()
{
    _busy = true;                                // 전환 중 재진입 방지
    _stateController.ChangeState(GameState.Loading);
    await _sceneLoader.LoadAsync(TITLE_SCENE, _scope);   // _scope = GameLifetimeScope
    _stateController.ChangeState(GameState.Title);
    _busy = false;
}

SceneLoader.LoadAsync의 핵심:

using (LifetimeScope.EnqueueParent(parent))          // "다음에 Awake하는 LifetimeScope는 parent를 부모로"
{
    await SceneManager.LoadSceneAsync("Title", Single);   // 이 안에서 TitleLifetimeScope.Awake 발생
}
  • Single 모드 → Bootstrap이 언로드된다. 그러나 GameLifetimeScope는 DontDestroyOnLoad라 살아남는다.
  • EnqueueParent 덕분에 새로 뜨는 TitleLifetimeScope의 부모가 GameLifetimeScope로 연결된다 — 자식 스코프가 부모 컨테이너의 등록물을 주입받을 수 있게.
  • using 블록이 await를 가로질러 열려 있다. 새 씬의 LifetimeScope.Awake가 로드 도중에 실행되므로, 그 시점까지 부모 지정이 유효해야 하기 때문.

Title 씬 구성과 주입

씬 구성: Camera, EventSystem, TitleLifetimeScope(GO), Canvas(제목 텍스트 + Start/Quit 버튼 + TitleMenu 컴포넌트).

TitleLifetimeScope.Configure()
  └ builder.RegisterComponentInHierarchy<TitleMenu>()
      → 씬에서 TitleMenu 를 찾아 등록 + [Inject] Construct(GameFlow) 호출
        (GameFlow 는 부모 컨테이너의 싱글턴 → 그 인스턴스를 주입)

TitleMenu는 OnEnable에서 버튼 onClick 리스너를 걸고 OnDisable에서 해제한다(씬을 나갈 때 자동 정리).

  • Start → _startButton.interactable = false(더블클릭 방지) + _gameFlow.StartGame().Forget()
  • Quit → 에디터면 isPlaying = false, 빌드면 Application.Quit()

StartGame — World 씬 로드

public async UniTask StartGame()
{
    if (_busy || _stateController.CurrState != GameState.Title)
        return;                                     // 가드

    _busy = true;
    _stateController.ChangeState(GameState.Loading);
    await _sceneLoader.LoadAsync(WORLD_SCENE, _scope);
    _stateController.ChangeState(GameState.Playing);
    _busy = false;
}

World가 Single 로드되면서 Title이 언로드되고 TitleLifetimeScope가 파괴된다(리스너는 OnDisable로 정리). GameLifetimeScope는 여전히 생존.

World가 뜨면 WorldLifetimeScope가 씬에서 GooseController · CameraDirector · ObjectiveHudView · PauseMenuView를 찾아 주입하고, WorldFlow가 음악 + Area_Garden을 Additive 로드한다. ChangeState(Playing) 발행 → StateChanged → PauseMenuView.OnStateChanged(Loading→Playing) → 패널은 계속 숨김.

일시정지 — 왜 GameFlow가 소유하나

Playing ⇄ Paused는 앱 전역 흐름의 일부이고, timeScale · 입력 차단은 게임플레이 씬이 살아있는 채로 조작해야 한다. GameFlow는 GameLifetimeScope에 상주하므로 씬 전환과 무관하게 이 상태를 안정적으로 관리한다. PauseMenuView는 뷰일 뿐 — 상태를 만들지 않고 반영만 한다.

Esc를 눌렀을 때

  1. InputService: UI/Cancel 액션 performed → PausePerformed 이벤트.

  2. GameFlow.TogglePause():

    if (_busy) return;
switch (_stateController.CurrState)
{
    case GameState.Playing: SetPaused(true);  break;
    case GameState.Paused:  SetPaused(false); break;
}

  3. SetPaused(true):

    Time.timeScale = 0;                              // Update deltaTime · 물리 · 애니메이션 정지
_inputService.SetGameplayInputEnabled(false);   // Player 맵 Disable → 구스 안 움직임
_stateController.ChangeState(GameState.Paused);

  4. ChangeState(Paused) → OnStateChanged → StateChanged → PauseMenuView.OnStateChanged: _panel.SetActive(next == Paused) → 패널 ON.

왜 UI/Cancel 액션을 따로 켜두나

일시정지 중엔 Player 맵을 끄는데(SetGameplayInputEnabled(false)), 해제 입력은 계속 받아야 한다. 그래서 _pause 액션만 InputService.Initialize()에서 독립적으로 Enable() 해둔다.

Resume 클릭

PauseMenuView.OnResumeClicked → _gameFlow.TogglePause() → 지금 Paused → SetPaused(false) → timeScale = 1, 입력 복구, ChangeState(Playing) → 패널 OFF.

Quit to Title 클릭

public async UniTask ReturnToTitle()
{
    if (_busy || (CurrState != GameState.Playing && CurrState != GameState.Paused))
        return;

    SetPaused(false);                // timeScale=1 먼저 복구 (안 하면 Title 씬이 멈춘 채로 뜸)
    _audioService.StopMusic(false);
    await GoToTitle();               // Loading → Title Single 로드(World+Area 언로드) → Title
}

SetPaused(false)에는 가드가 있어서 Paused면 정상 복구, 이미 Playing이면 no-op이다 — timeScale 리셋을 안전하게 위임한다.

02

async · await · UniTask

코루틴을 써봤으면 사실상 다 아는 것이다. async / await는 코루틴의 문법만 바꾼 것이라고 봐도 된다. 아래에서 주황은 코루틴 쪽, 청록은 async 쪽을 가리킨다.

한 줄 대응

코루틴async / await의미
IEnumerator 반환async UniTask 반환"이 함수는 중간에 멈췄다 이어질 수 있다"
yield return ...await ..."이거 끝날 때까지 여기서 멈춰라"
yield return nullawait UniTask.Yield()1프레임 대기
yield return new WaitForSeconds(2)await UniTask.Delay(2000)2초 대기
yield return StartCoroutine(Other())await Other()다른 비동기 함수 끝날 때까지 대기

StopCoroutineCancellationToken중단
결과값 못 받음 (필드 / 콜백 우회)var x = await LoadThing();await가 값을 돌려준다

각 키워드

async
"이 메서드 안에 await가 있다"는 표시. 컴파일러가 이걸 보면 메서드를 코루틴처럼 상태기계로 재작성한다 — await 지점마다 잘라서, 나중에 그 지점부터 이어서 실행하게. 코루틴 컴파일러가 IEnumerator에 하는 일과 똑같다.
await
"이 작업 끝날 때까지 이 메서드를 여기서 멈춰라. 끝나면 다음 줄부터 이어서." 멈춰 있는 동안 게임의 나머지 코드(Update 등)는 계속 돈다. 스레드를 막지 않는다. yield return과 같은 감각.
UniTask
"진행 중인 비동기 작업의 손잡이." 코루틴의 Coroutine 객체에 대응한다 — 단, await로 완료를 기다릴 수 있고 UniTask<T>는 결과값을 돌려준다. .NET 표준 Task는 힙 할당이 있어 GC 부담이 있고, UniTask는 struct 기반 무할당 + Unity PlayerLoop에 통합돼서 Unity에선 사실상 표준이다.

나란히 비교

동작은 완전히 동일하다 — "시작" 즉시 출력 → 제어 반환(게임 계속 돌아감) → 2초 뒤 "2초 후".

코루틴
IEnumerator Example()
{
    Debug.Log("시작");
    yield return new WaitForSeconds(2f);
    Debug.Log("2초 후");
}

StartCoroutine(Example());
async / await
async UniTask ExampleAsync()
{
    Debug.Log("시작");
    await UniTask.Delay(2000);
    Debug.Log("2초 후");
}

ExampleAsync().Forget();

StartAsync가 실제로 하는 일 (프레임 단위)

public async UniTask StartAsync(CancellationToken cancellation)
{
    _stateController.OnStateChanged += OnStateChanged;   // ① 즉시 실행
    _inputService.PausePerformed    += TogglePause;      // ② 즉시 실행
    await GoToTitle();                                   // ③ 여기서 멈춤
}

  1. 프레임 N (VContainer가 컨테이너를 빌드하면서 호출):

    += OnStateChanged 실행 → += TogglePause 실행 → await GoToTitle() 도달.

  2. GoToTitle 안으로 들어가 _busy = true, ChangeState(Loading)까지 즉시 실행.

  3. 그 안의 await _sceneLoader.LoadAsync("Title") 도달 → 씬 로딩은 여러 프레임 걸린다 → StartAsync가 호출자(VContainer)에게 제어를 돌려준다. 컨테이너 빌드 계속, 게임 루프 계속.

  4. 프레임 N + 몇: 씬 로딩 완료 → LoadAsync의 await 풀림 → GoToTitle 이어서: ChangeState(Title), _busy = false → GoToTitle 끝 → StartAsync의 await도 풀림 → 종료.

요점

StartAsync는 한 번 호출됐지만 여러 프레임에 걸쳐 조각조각 실행된다. 코루틴과 똑같다.

CancellationToken cancellation

VContainer가 넘겨주는 "취소 신호". 스코프가 파괴되면 이 토큰이 '취소됨' 상태가 된다. 코루틴에서 GameObject가 꺼지면 자동으로 멈추는 것 ≈ 이 토큰.

차이: async는 자동으로 안 멈춘다. 긴 작업이면 직접 await Something().AttachExternalCancellation(cancellation) 같은 식으로 "취소되면 중단"을 걸어줘야 한다. 우리 StartAsync는 짧아서 지금은 안 쓰지만, IAsyncStartable 인터페이스가 시그니처에 요구하기 때문에 파라미터가 있다.

.Forget()

async 메서드를 호출하고 await 안 하면 컴파일러가 경고한다("안 기다리는데 괜찮아?"). .Forget()은 UniTask 확장 메서드로:

  • "일부러 안 기다린다, 실행만 하고 잊는다"를 명시
  • 그 안에서 터진 예외를 삼키지 않고 로그로 뱉음

버튼 핸들러(void OnStartClicked())에서 _gameFlow.StartGame()을 호출할 때 쓴다. 버튼 콜백은 void라 await가 불가능하니까.

코루틴과 다른 점 (주의)

  1. async void는 쓰지 마라. 예외를 잡을 수 없다. 항상 async UniTask. (반환을 안 기다릴 땐 .Forget())
  2. 자동으로 안 멈춘다. GameObject가 꺼져도 계속 돈다 → CancellationToken으로 관리.
  3. 예외가 await 체인을 타고 위로 전파된다. 코루틴은 에러 나면 조용히 멈추지만, async는 StartAsync → GoToTitle → LoadAsync 어디서 터져도 위로 올라온다.
  4. await 다음 줄은 (UniTask 기본) 메인 스레드에서 이어진다 → Unity API 호출 안전.

왜 여기서 코루틴 대신 async를 쓰나

GameFlow는 MonoBehaviour가 아니다(VContainer가 관리하는 순수 C# 클래스). StartCoroutine을 못 쓴다. async / await는 아무 클래스에서나 되고, 값 반환 · 예외 전파가 되고, StartAsync → GoToTitle → SceneLoader.LoadAsync → SceneManager.LoadSceneAsync처럼 여러 계층을 깔끔하게 관통한다.
