Fantasy World · 오디오 설계 노트

FMOD 적용 계획

거위 게임(Untitled Goose Game 류)에 FMOD Studio 를 어떻게 쓸지 — 기능 우선순위, 핵심 개념, 낮/밤 · 날씨 · 공간감 설계.

FMOD 의 핵심은 "소리를 실행"이 아니라 "게임 상태를 파라미터로 알려주면 사운드가 알아서 반응" 이다. 코드는 파라미터 값만 던지고, 반응(믹싱·전환·레이어)은 전부 Studio 에서 저작한다.

1. 현재 상태

지금 AudioService 가 제공하는 것:

  • PlayOneShot(EventReference, Vector3) — 일회성 SFX (위치 기반)
  • PlayMusic / StopMusic / SetMusicParameter — 음악 하나 유지
  • SetGlobalParameter(name, value) — 전역 파라미터

"위치가 잡히는 AudioSource" 수준. FMOD 뱅크가 아직 없어서 실제 소리는 안 남 (EventReference.IsNull 가드로 안전하게 무시).

2. 아키텍처 연결

FantasyWorld.Core AudioService 재생 래퍼. FMOD API 를 감싸기만 함. "무엇을" 은 모름. FantasyWorld.World GameSounds (SO) 게임플레이 사운드 EventReference 카탈로그 (Honk / Grab / Drop / ...) GameplayAudioDirector GameplayEventBus 구독 → 이벤트에 맞는 GameSounds 항목을 AudioService 로 재생 EnvironmentService (예정) 게임 시간·날씨 관리 → AudioService.SetGlobalParameter 로 반영 + 조명 / 스카이박스도 같이
원칙: 무코드로 되는 건 코드에 안 넣는다. StudioListener(카메라), StudioEventEmitter(앰비언스 루프), StudioParameterTrigger(콜라이더 → 파라미터), StudioBankLoader(구역 뱅크) 는 씬 컴포넌트로 처리.

3. 기능 우선순위

Tier 1 반드시

없으면 FMOD 를 쓰는 의미가 없는 것들.

3-1. FMOD Studio 프로젝트 + 뱅크 파이프라인 (전제조건)

.fspro 생성 → 이벤트 저작 → 뱅크 빌드 → Assets/StreamingAssets → FMODStudioSettings 에 뱅크 등록. 이게 없으면 아래 전부 못 한다. (.gitignore 에 뱅크 파일 제외 규칙 이미 있음)

3-2. Parameters (로컬 + 글로벌) — 가장 중요

"이벤트를 실행"이 아니라 "이벤트한테 상황을 알려주면 알아서 반응".

파라미터종류우리 게임

코드는 이미 준비됨. Studio 에서 파라미터 만들고 타임라인에 조건·자동화 걸면 끝.

3-3. Buses + VCA (믹서 구조)

bus:/ ├─ SFX (VCA: SFX) ├─ Music (VCA: Music) ├─ Ambience (VCA: Ambience) └─ Reverb (send 전용)
  • 설정 메뉴 볼륨 슬라이더 → VCA 볼륨 (SettingsService 가 건드림)
  • 버스 단위 일시정지 / 페이드 / 덕킹

3-4. 3D 이벤트 + StudioListener

  • Studio 에서 이벤트를 3D 로 저작 (min/max distance, attenuation curve)
  • Unity: 카메라(또는 구스)에 StudioListener 컴포넌트
  • → 정원사 발소리가 다가올수록 커지고 좌우로 팬됨. PlayOneShot(event, position) 은 이미 위치를 넘기고 있음

4. 핵심 개념 — 덕킹

덕킹 = 한 소리가 나는 동안 다른 소리를 자동으로 살짝 죽였다가, 끝나면 되돌리는 것. (라디오 DJ 말할 때 음악 작아지는 것)

앰비언스 덕킹 = honk · 물건 깨짐 · 정원사 고함 같은 중요한 SFX 가 날 때 배경 앰비언스(새소리·바람·웅성거림)를 순간 -4~6dB → 중요한 소리가 앰비언스를 "뚫고" 들림. 끝나면 스르륵 복귀.

Studio: bus:/Ambience 에 Compressor, sidechain input 을 bus:/SFX(또는 특정 이벤트)로 연결. SFX 레벨이 커질수록 앰비언스가 눌림.
코드: 없음. 저작만.

5. 낮/밤 시스템 + 환경별 사운드

핵심 패턴: 글로벌 파라미터 하나 (TimeOfDay, 0~24). 시간 시스템이 값을 밀어넣고, 반응은 전부 Studio.

// EnvironmentService (새 Core 서비스) 가 매분 / 변화 시
_audioService.SetGlobalParameter("TimeOfDay", currentHour);
// 이 서비스가 조명 · 스카이박스도 같이 갱신

Studio 에서 TimeOfDay 를 타임라인 축으로 쓰는 "Village Ambience" 이벤트:

시간레이어
0 ~ 5귀뚜라미, 부엉이, 정적
6 ~ 9새 지저귐 폭발, 닭, 활동 시작
10 ~ 17낮 소음, 멀리 개
18 ~ 21저녁, 새 잦아듦
22 ~ 24밤으로 크로스페이드

각 레이어(instrument)가 파라미터 값에 따라 자동화 커브로 페이드 인/아웃. 음악도 밤엔 잔잔한 스템으로, 발소리 리버브도 밤엔 더 (거리가 조용하니).

환경 변화 = 파라미터 1개. StudioGlobalParameterTrigger 는 콜라이더 기반이라 시간엔 안 맞음 → 코드로 세팅한다.

6. 공간감 + "비 올 때 자연스럽게 묻힘"

"묻힘"을 만드는 층위가 여러 개다. 조합해서 쓴다.

(a) Snapshot "Raining" — 가장 통제 잘 되는 방법

믹서 상태를 정의하고, 비 강도(Weather 파라미터)에 블렌드 비율을 연동:

Snapshot "Raining" (intensity ← Weather 파라미터) bus:/Ambience.Rain 페이드인 (+8dB) bus:/SFX -3dB bus:/Music -2dB + 하이컷 살짝 (비 오면 답답한 느낌) Reverb send + (젖은 공간감) Master LP 필터 살짝 (전체 muffle)

갑자기 쏟아지면 스냅샷이 0.5초 페이드인 → 다른 소리들이 스르륵 뒤로 물러남.

(b) Sidechain — 비가 다른 걸 눌러줌

bus:/SFX · bus:/Music 에 Compressor, sidechain 을 Rain 이벤트에서. 비가 셀수록 나머지가 눌림. (a)랑 같이 쓰면 더 유기적.

(c) 주파수 마스킹 — 물리적으로 그냥 됨

비는 광대역 노이즈라 다른 소리의 중고역을 자연히 가린다. 억지로 안 해도 됨. 단, honk · 정원사 목소리는 묻히면 안 됨 → 얘넨 sidechain 에서 제외하거나, 재생될 때 역방향으로 Rain 을 짧게 덕킹 ("비 오는데 honk 는 뚫고 나옴").

(d) 공간감 기반 (날씨와 별개로 항상)

기법StudioUnity / 코드
3D 이벤트 + StudioListener3D 저작, min/max distance, Doppler카메라에 StudioListener (3D · pan · Doppler 자동)
구역별 리버브Reverb 스냅샷 (야외 드라이 / 헛간 우드 / 골목 반사)StudioParameterTrigger (콜라이더) 또는 스코프에서 스냅샷
오클루전 (벽 뒤 소리 답답)Occlusion 로컬 파라미터 → LP 필터 자동화레이캐스트로 막혔으면 파라미터 세팅 (Npc.CanSeeGoose 와 유사)

7. 착수 순서

  1. FMOD Studio 프로젝트 + 뱅크 빌드 파이프라인
  2. bus:/ 아래 SFX / Music / Ambience / Reverb(send)
  3. Chase 글로벌 파라미터 → GameplayAudioDirector 가 NPC Alerted 에 물림
    "추격당하면 음악이 바뀐다" 를 최소 구현으로 먼저 경험
  4. 발소리를 Surface 파라미터 + Multi instrument 로
  5. 적응형 음악 본격 저작 (transition / sustain / tempo)
  6. 스냅샷 (Paused 부터 → Chased → Raining)
  7. EnvironmentService 만들고 TimeOfDay / Weather 파라미터 연동
  8. 구역별 Reverb 스냅샷 + per-area 뱅크 로드
3번까지만 해도 "아 이래서 FMOD 를 쓰는구나" 가 된다.

8. AudioService 확장 방향

// 지금
PlayOneShot / PlayMusic / StopMusic / SetMusicParameter / SetGlobalParameter

// 추가될 것
SetBusVolume(string bus, float v)      // 설정 메뉴 → VCA / Bus
LoadBankAsync / UnloadBank             // 구역별
SetPaused(bool)                        // Paused 스냅샷 or PauseAllEvents
SetSnapshot(string name, bool on)      // Raining / Indoors / ...
// 리스너 전환 등

최종적으로 게임 코드가 하는 일은 이게 거의 전부: 

_audioService.SetGlobalParameter("TimeOfDay", hour);
_audioService.SetGlobalParameter("Weather", rainIntensity01);
_audioService.SetGlobalParameter("Chase", chaseLevel);

나머지 90% 는 Studio 저작. FMOD 의 설계 철학이 "게임은 상태만 알려주고, 사운드 디자이너가 반응을 만든다".
