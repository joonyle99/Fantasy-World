await는 어디까지 기다리나

GameFlow가 await LoadAsync("World")로 World 씬을 부르고, 그 안에서 WorldFlow가 다시 await LoadAdditiveAsync("Area_Garden")를 한다. 이 두 await가 하나의 사슬로 이어지는가 — 아니면 별개인가.

대상 파일  GameFlow.cs  WorldFlow.cs  SceneLoader.cs  WorldLifetimeScope.cs

← 관련: GameFlow와 async 노트 · LifetimeScope와 주입 노트

세 줄 답

  1. GameFlow의 await는 "World 씬 로드"까지만 기다린다. World.unity의 오브젝트들이 다 생기고 Awake/OnEnable이 끝나면 풀린다.
  2. WorldFlow.StartAsync는 별개의 async 흐름이다. World 씬이 뜨면서 VContainer가 따로 시작시킨다. GameFlow는 그것을 기다리지 않고, 참조조차 없다.
  3. 두 흐름은 사슬이 아니라 나란히 겹쳐 흐른다. GameFlow가 Playing으로 넘어간 뒤에도 WorldFlow는 아직 Area_Garden을 로드하는 중일 수 있다.
01

두 흐름은 이어지지 않는다

GameFlow의 await는 무엇을 기다리나

GameFlow.StartGame:

_busy = true;
_stateController.ChangeState(GameState.Loading);
await _sceneLoader.LoadAsync(WORLD_SCENE, _scope);   // ← 여기서 GameFlow 정지
_stateController.ChangeState(GameState.Playing);
_busy = false;

SceneLoader.LoadAsync 안을 보면, 실제로 기다리는 대상은 Unity의 AsyncOperation 하나다:

using (LifetimeScope.EnqueueParent(parent))
{
    var operation = SceneManager.LoadSceneAsync(sceneName, LoadSceneMode.Single);
    await operation;   // ← GameFlow의 await는 결국 이 operation의 완료를 기다린다
}

LoadSceneMode.Single인 이 operation은 새 씬이 활성화되고 그 씬 오브젝트들의 Awake · OnEnable이 모두 실행된 시점에 완료된다. (Start()는 그 다음 프레임)

그 활성화 도중에 WorldLifetimeScope.Awake()도 돌아서 — 컨테이너 빌드 → WorldFlow 인스턴스 생성까지는 끝난다. 하지만 WorldFlow가 Area_Garden을 로드하는 것은 아직이다.

그래서

GameFlow의 await LoadAsync("World")가 풀리는 순간, Area_Garden은 거의 확실히 아직 로드 안 됨. WorldFlow.StartAsync는 막 시작됐거나, 자기 await에서 멈춰 있는 상태.

WorldFlow.StartAsync는 누가 부르나

WorldFlow는 WorldLifetimeScope.Configure에서 RegisterEntryPoint<WorldFlow>()로 등록됐고, IAsyncStartable을 구현한다.

public async UniTask StartAsync(CancellationToken cancellation)
{
    _audioService.PlayMusic(_sounds.Music);                              // 즉시
    await _sceneLoader.LoadAdditiveAsync("Area_Garden", _scope, setActive: true);
}
  • 이 StartAsync()는 VContainer의 엔트리포인트 디스패처가 호출한다 — WorldLifetimeScope의 컨테이너가 빌드된 직후.
  • VContainer는 StartAsync()가 반환한 UniTask를 GameFlow 쪽으로 연결하지 않는다. (취소 토큰으로 수명만 추적할 뿐, 아무도 이 UniTask를 await 하지 않음 — fire and forget)
  • GameFlow는 WorldFlow에 대한 참조가 없다. 기다리려야 기다릴 수단이 없다.

즉 WorldFlow.StartAsync는 GameFlow 흐름의 연속이 아니라, World 씬이 뜨면서 독립적으로 새로 시작된 흐름이다. 둘은 형제지 부모-자식이 아니다.

02

프레임 단위 타임라인

Title에서 Start를 눌러 World로 들어가는 경우. 배지 색이 어느 흐름인지 나타낸다.

GameFlow 흐름 WorldFlow 흐름 Unity / VContainer

  1. GameFlowStartGame(): _busy=true, ChangeState(Loading), await LoadAsync("World") → 여기서 정지. 제어가 호출자에게 반환됨.

  2. UnityWorld.unity를 여러 프레임에 걸쳐 로드. Bootstrap 언로드되지만 GameLifetimeScope는 DontDestroyOnLoad라 생존.

  3. UnityWorld 씬 활성화. 모든 오브젝트의 Awake 실행 — WorldLifetimeScope.Awake가 먼저(실행 순서 앞당겨짐) → 컨테이너 빌드 → GooseController·CameraDirector·ObjectiveHudView·PauseMenuView 주입, WorldFlow 인스턴스 생성. 이어서 모든 OnEnable.

  4. UnityWorld 씬 로드 AsyncOperation 완료.

  5. GameFlowawait LoadAsync("World") 풀림 → ChangeState(Playing) → _busy=false → GameFlow 흐름 종료.

  6. WorldFlowVContainer가 WorldFlow.StartAsync() 호출 — 여기서부터 완전히 새 흐름.

    5번과 6번의 정확한 선후는 PlayerLoop 타이밍에 달렸지만 중요하지 않다. 6~11은 5와 무관하게 진행된다.

  7. WorldFlow_audioService.PlayMusic(...) 즉시 실행.

  8. WorldFlowawait LoadAdditiveAsync("Area_Garden") → 여기서 정지.

  9. UnityArea_Garden.unity를 여러 프레임에 걸쳐 Additive 로드. World 씬 위에 얹힘.

  10. UnityArea 씬 활성화. AreaLifetimeScope.Awake(부모 = WorldLifetimeScope) → AreaFlow 등 생성 → AreaFlow.Start()가 목표 세트를 ObjectiveManager에 등록.

  11. WorldFlowawait LoadAdditiveAsync 풀림 → StartAsync 끝 → WorldFlow 흐름 종료.

읽는 법

배지 1–5는 GameFlow가 await 하나(World 로드)를 걸고 풀리는 전부다. 6–11은 그 뒤에 시작되는 WorldFlow의 독립된 흐름 — GameFlow는 이걸 보지도, 기다리지도 않는다.

코루틴으로 옮기면

// GameFlow — 버튼 핸들러가 시작
IEnumerator GameFlowRoutine()
{
    yield return SceneManager.LoadSceneAsync("World", Single);   // World 씬 로드까지만 대기
    state = Playing;
}

// WorldFlow — World 씬이 뜨면 WorldLifetimeScope가 "따로" 시작시킨다
IEnumerator WorldFlowRoutine()
{
    PlayMusic();
    yield return SceneManager.LoadSceneAsync("Area_Garden", Additive);
}

GameFlowRoutine은 WorldFlowRoutine을 yield return 하지 않는다. WorldFlowRoutine은 다른 주체가 StartCoroutine으로 따로 돌리는 완전히 별개의 코루틴이다. 서로의 완료를 기다리지 않는다. async 버전도 정확히 이 관계다.

03

그래서 무엇이 달라지나

GameState.Playing은 "World 씬 로드 완료" 시점에 설정된다 — "첫 구역이 플레이 가능해진 시점"이 아니다.

그 사이 몇 프레임 동안: 구스 · 카메라 · HUD · 일시정지 메뉴는 이미 있지만(World.unity), Area_Garden의 바닥 · 소품 · NPC · 목표존은 아직 없다. 구스가 바닥이 생길 자리로 낙하할 수도 있다. 보통은 Additive 로드가 빠르거나 로딩 화면으로 가린다.

설계 노트

Loading 상태를 Area_Garden 준비 완료까지 늘리고 싶다면 — 지금 구조로는 안 된다. WorldFlow가 완료를 이벤트로 알리거나, GameFlow가 구역 로드를 직접 await 해야 한다. (예: WorldFlow가 UniTaskCompletionSource를 노출하고 GameFlow가 그걸 await)

전체 체인 요약

흐름await 대상언제 풀리나다음 흐름을 기다리나?
GameFlow → GoToTitle LoadAsync("Title") Title.unity 활성화 (Awake/OnEnable 끝) ✗ TitleMenu 이후는 유저 입력 대기
GameFlow → StartGame LoadAsync("World") World.unity 활성화 ✗ WorldFlow를 안 기다림 → 바로 Playing
WorldFlow → StartAsync LoadAdditiveAsync("Area_Garden") Area_Garden.unity 활성화 ✗ AreaFlow.Start 이후는 별개
AreaFlow 없음 (IStartable, 동기 Start()) — —

await가 이어지는 유일한 구간은 한 흐름 안에서다: GameFlow.StartGame → SceneLoader.LoadAsync → SceneManager.LoadSceneAsync. 흐름과 흐름 사이(GameFlow ↔ WorldFlow ↔ AreaFlow)는 씬 로드가 만드는 느슨한 연결일 뿐, await로 묶여 있지 않다.
